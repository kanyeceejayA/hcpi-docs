    Using the System — A UI Walkthrough

    This page is the literal click-by-click guide to running HCPI in the Odoo web interface: which menu, which form, which button label, in what order. If How the Calculations Work tells you what the system computes, this page tells you how to make it compute.

    It assumes a fresh, empty HCPI instance. If you already have a running country instance, skip Phase 0 (setup) and jump to Phase 2 — Collecting prices (monthly).

    The HCPI navbar at a glance

    When you log into Odoo and open HCPI, the top navbar shows these root menus, left to right (in sequence order):

    Menu What it's for
    Dashboard Landing page with key index summaries
    Data Collection Field questionnaires (hcpi.data.collection) and validation batches (hcpi.data.validation)
    Indices Index results, the seven computation wizards (numbered 1️⃣–7️⃣), and computation history
    COICOP The product-classification ladder: Divisions → Groups → Classes → Sub Classes → Micro Classes → Elementary Aggregates
    Items The item catalogue and Units of Measure
    Outlets Outlets, outlet items, observations, consumption segments, and EA weights

    The monthly working rhythm only really uses Data Collection and Indices. The other three menus are mostly one-time configuration that you barely touch after the first setup.

    Phase 0 — One-time setup (a fresh instance)

    You only do this once when standing up a new country instance. Order matters: each step depends on the one above.

    0.1 Build the COICOP classification ladder

    Menu: COICOP

    Build it top-down, in this exact order — each level points to its parent:

    1. COICOP → Divisions → click New → fill in COICOP code and name (e.g. "01 — Food and non-alcoholic beverages") → Save.
    2. COICOP → Groups → New → pick the Division → Save.
    3. COICOP → Classes → New → pick the Group → Save.
    4. COICOP → Sub Classes → New → pick the Class → Save.
    5. COICOP → Micro Classes → New → pick the Sub Class → Save.
    6. COICOP → Elementary Aggregates → New → pick the Micro Class → Save. (This is the rung where the index actually starts being computed — see Stage 4 of the calculations page.)

    0.2 Define units of measure and items

    Menu: Items

    1. Items → Units of Measure → New → for each unit you'll record prices in (kg, litre, piece, …).
    2. Items → Items → New. For each item: name (e.g. "White bread loaf, 500 g"), link to its Elementary Aggregate and Micro Class, set the standard quantity and standard unit.

    The link to the Elementary Aggregate is the chain that, weeks later, will route the item's price up the right COICOP ladder.

    0.3 Define consumption segments (the "baskets")

    Menu: Outlets → Consumption Segments

    Click New, name the segment (e.g. "Kampala Urban", "Rural North"), save. You will create one segment per population stratum — each one has its own weights and produces its own basket-level index.

    0.4 Define outlets

    Menu: Outlets

    1. Outlets → Configuration → Outlet Types → New → categories like "Supermarket", "Open market stall", "Pharmacy". (Reusable across all outlets.)
    2. Outlets → Outlets → New → name, address, outlet type, and the consumption segment it belongs to.
    3. Open the outlet form. In the header, click "Add Items" (header button, visible to users in the Outlet Manager group). This opens a wizard that lets you link multiple items at once to this outlet and record each item's base price (the reference-period price each long-term relative is measured against).

    After this, each link is an hcpi.outlet.item record — visible under Outlets → Outlet Items.

    0.5 Enter EA weights

    Menu: Outlets → Elementary Aggregate Weights

    Click New, pick an Elementary Aggregate and a Consumption Segment, type in the weight (the household expenditure share of that EA in that basket), save. Repeat for every (EA × segment) pair.

    Weights are the only thing stored manually above the EA

    Every higher-level weight (class, group, division, basket) is the sum of the EA weights beneath it — computed automatically. You never enter a class weight or a division weight by hand.

    Phase 1 — Designing the monthly questionnaire (optional helpers)

    Before enumerators go into the field, you may want to bulk-generate or assign their questionnaires.

    Menu: Data Collection

    • Data Collection → Bulk Questionnaires — wizard to create many hcpi.data.collection records at once (one per outlet × month).
    • Data Collection → Assign Questionnaires — wizard to assign collectors and supervisors in bulk.

    If your team creates questionnaires one at a time on phones, you can skip both.

    Phase 2 — Collecting prices (monthly)

    This is what enumerators do at the start of every month.

    Menu: Data Collection → Data Collection

    2.1 Create or open a questionnaire

    Click New, pick the Outlet, the Collection Date, and the Consumption Segment. Assign a Data Collector and Supervisor. Save. State is now draft.

    2.2 The state machine — the buttons in the form header

    The collection record walks through five states. The header button you see changes with the state:

    flowchart LR
    D["draft<br/>state"] -->|"Approve"| S["survey<br/>state"]
    S -->|"Standardize"| ST["standardization<br/>state"]
    ST -->|"Validate Prices"| V["validation<br/>state"]
    V --> DN["done<br/>state"]
    D -.->|"Cancel"| C["cancel<br/>state"]
    C -.->|"Reset to Draft"| D
    V -.->|"Reject"| ST
    V -.->|"Reset to Standardization"| ST

    The actual button labels (verbatim from the form):

    Button When visible What it does
    "Approve" state = draft Marks the questionnaire ready for collection (state → survey); calls approve()
    "Cancel" state = draft Voids the questionnaire (state → cancel); calls cancel()
    "Standardize" state = survey Normalises each line's price to the item's standard quantity/unit, producing standard_price; calls standardize()
    "Validate Prices" state = standardization Commits the questionnaire for validation; calls validate()
    "Reject" state = standardization Sends back to draft with a reason form; calls action_open_reject_view()
    "Reset to Draft" state = cancel Restarts the workflow
    "Reset to Standardization" state = validation Allows re-entering prices after validation has begun

    2.3 Add the price lines

    In the form's "Observations" tab, add one line per item priced at this outlet today. Each line is an hcpi.data.collection.line and at minimum needs: outlet item, observed price, observed quantity (and unit if different from the item's standard).

    2.4 Move it through the workflow

    Once all lines are entered: Approve → Standardize → Validate Prices.

    When you click Validate Prices, the system automatically groups all lines for the same basket × month into a hcpi.data.validation record — the batch that the Tukey check will run on next.

    Phase 3 — Validating prices (the Tukey check)

    This is what supervisors do to clean the month's prices before they become permanent observations. One validation record covers one consumption segment × month.

    Menu: Data Collection → Data Validations

    Open a validation record (the one auto-created at the end of Phase 2). State is draft.

    3.1 The state machine — the buttons in the form header

    flowchart LR
    D["draft<br/>state"] -->|"Validate"| V["validation<br/>state"]
    V -->|"Validate Inliers"| VI["validate_inliers<br/>state"]
    VI -->|"Impute"| I["imputation<br/>state"]
    I --> DN["done<br/>state"]
    D -.->|"Reset to Draft"| D

    The buttons:

    Button When visible What it does
    "Validate" state = draft Runs the Tukey outlier algorithm — see Stage 3 of the calculations page. Internally calls action_validate() which runs run_turkey(). State → validation.
    "Validate Inliers" state = validation Flags items whose price has been identical for 12 months (potential forgotten entries). Internally calls action_validate_inliers() which runs validate_inliers(). State → validate_inliers.
    "Impute" state = validate_inliers Fills gaps by climbing the COICOP ladder (impute_with_prices → impute_with_ea → impute_with_micro_class → …). Confirmation prompt: "Please note that this action confirms the current inliers and outliers before proceeding with imputation." Calls action_impute(). State → imputation → done.
    "Reset to Draft" any non-draft state Restarts the validation workflow

    3.2 Reviewing what the algorithm flagged

    The validation form has stat buttons (the round counters at the top-right of the form) that take you to filtered list views:

    • Inliers — items flagged as suspiciously unchanging (action_open_inliers())
    • Outliers — items flagged as suspiciously moving (action_open_outliers())
    • Imputed Prices — items where the system filled a gap (action_open_imputed())

    A supervisor's job is to walk these lists, accept/reject each flagged price, and then click the next workflow button. Once Impute runs and state goes to done, the surviving prices become permanent hcpi.outlet.item.observation records and are visible under Outlets → Price Data.

    Phase 4 — Computing the indices (monthly, strictly in order)

    This is the heart of the monthly cycle. Each wizard is a separate menu entry, numbered to remind you of the order — do not skip ahead, each one reads from the level below.

    Menu: Indices → Computations

    flowchart TD
    A["1️⃣ Update EA Indices<br/><i>geometric mean (Jevons) per EA × segment × month</i>"] --> B["2️⃣ Update Basket COICOP Indices<br/><i>weighted mean: micro → sub → class → group → division</i>"]
    B --> C["3️⃣ Update Basket Indices<br/><i>headline per consumption segment</i>"]
    C --> D["4️⃣ Update National Indices<br/><i>weighted across all baskets</i>"]
    A -.-> E["5️⃣ Update Special Indices<br/><i>custom EA groups: Energy, Core…</i>"]
    B -.-> F["6️⃣ Update Classification Indices<br/><i>custom class groups: Food/Non-food…</i>"]
    C -.-> G["7️⃣ Update Domestic Indices<br/><i>regional subsets</i>"]

    4.1 The four mandatory wizards (run in this order)

    Step Menu Wizard (model) The button Method called
    1️⃣ Indices → Computations → Update EA Indices hcpi.ea.index.update "Start Update" action_update_ea_indices()
    2️⃣ Indices → Computations → Update Basket COICOP Indices hcpi.basket.coicop.index.update "Start Update" action_update_basket_coicop_indices()
    3️⃣ Indices → Computations → Update Basket Indices hcpi.basket.index.update "Start Update" action_update_basket_indices()
    4️⃣ Indices → Computations → Update National Indices hcpi.national.index.update "Start Update" action_update_national_indices()

    In each wizard's form, fill in the date range / segments to compute, then click "Start Update". The button is only enabled when the state is draft and the zero-price gate is satisfied. State flow: draft → processing → done (or failed).

    If you need to abort a long-running EA, Special, or Classification update, the form shows a "Cancel" button while state is processing (calls action_cancel()). Note: the Basket COICOP, Basket all-items, National, and Domestic wizards do not currently expose a cancel button while running — wait for them to finish or fail.

    4.2 The three optional / side-cut wizards

    Run any time after their dependency has run:

    Step Menu Wizard (model) Requires
    5️⃣ Indices → Computations → Update Special Indices hcpi.special.index.update EA indices (step 1)
    6️⃣ Indices → Computations → Update Classification Indices hcpi.classification.index.update Basket COICOP indices (step 2)
    7️⃣ Indices → Computations → Update Domestic Indices hcpi.domestic.index.update Basket indices (step 3)

    Same button — "Start Update" — same state flow.

    4.3 What happens if you click a wizard out of order?

    Each wizard checks that no other computation is already running before starting (mutual exclusion via a PostgreSQL advisory lock). It also reads whatever indices are currently in the database at the level below — so if you skip step 2 and run step 3, the basket all-items index will be computed from stale COICOP indices, not freshly-recomputed ones. The result will be technically valid but reflect last month's COICOP roll-up, not this month's.

    Rule of thumb: always run the chain end-to-end (1 → 2 → 3 → 4), then the optional side cuts.

    4.4 The zero-price safety gate

    If any active observation has observed_price = 0 in the month you're trying to compute, the "Start Update" button is disabled and a banner explains which month and which items are blocked. Fix the offending prices (Phase 2/3) and the button re-enables. See The zero-price safety gate for why this rule exists.

    Phase 5 — Viewing the results

    Once a computation finishes, the results are visible as read-only list views — no buttons, just data.

    What you want to see Menu path
    The headline national index by COICOP level Indices → National Indices → National Indices
    Regional / sub-population indices Indices → National Indices → Domestic Indices
    All-items index for one basket (e.g. "Kampala Urban") Indices → Basket Indices
    Drill-down by COICOP level for a basket Indices → Basket COICOP Indices → Division / Group / Class / … / Elementary Aggregate Indices
    Energy, Core, etc. Indices → Special Indices → National Special Indices (or Basket Special Indices)
    Food/Non-food, Goods/Services Indices → Classification Indices → National Classification Indices
    The Excel export Indices → Export Excel Workbook (wizard)
    Computation logs / history Indices → Computation History → pick the index type

    The default grouping in most index list views is by consumption segment or COICOP level, so you can collapse/expand to see a single segment's trajectory month-by-month.

    The monthly cycle, in one screen

    Print this and stick it on the wall:

    When something goes wrong

    Symptom Where to look What to do
    "Start Update" button is greyed out on a computation wizard The zero-price banner at the top of the wizard form Find the contaminated observations, fix them in Phase 2/3, then return
    Tukey threw out a price you think is real Data Collection → Data Validations → open the validation → Outliers stat button → review Untick is_outlier, then re-run "Impute" so the price is included
    Imputation filled a gap you'd rather leave empty Same place → Imputed Prices stat button Untick is_imputed, then re-run the affected index update
    Basket index looks wrong Indices → Basket COICOP Indices → Elementary Aggregate Indices Inspect the underlying EA indices and their diagnostics (recorded by _job_compute_indices_for_segment — see Stage 4)
    A computation hangs in processing Indices → Computation History Check the history record for error messages; if EA/Special/Classification, click "Cancel" in the wizard form
    Wizard won't start: "another computation is running" Indices → Computation History Wait for the running one to finish, or check whether a stale job needs to be cancelled
